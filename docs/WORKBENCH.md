# 工作台定制版

版本：`2.3.2`，versionCode `82`，运行协议 51。一步工作台提供设置中选择的最多十个常用应用、原生系统弹窗、统一的浅深色面板、顶部或底部控制区、侧窗原位扩展、横屏全屏视频收放，以及添加应用时保留原主窗任务。实际效果由用户真机验收。

## 窗口和外观

- 一个主窗加四个独立实时 VirtualDisplay 侧窗。侧窗点击交换、内部拖动、左右布局与任务退出恢复继续使用原来的任务协调器。
- 蓝色系深浅主题、渐变控制面板、圆角侧窗和主窗蓝色边框。功能按钮与空小窗共用同一卡片底色和描边，自绘图标按主题着色；第三方应用图标保持原样。主窗圆角由本模块的覆盖层绘制，不覆盖原生任务的圆角状态。
- 控制区左侧固定显示“格窗”和当前日期；右侧依次为比价、支付、设置齿轮三个 40dp 向量按钮（间距 8dp），标题行与常用栏作为整体在状态栏下方居中。齿轮直接打开 格窗设置（仍在工作台内）。常用栏先放设置里选择的应用（按所选顺序），其余位置按最近七天使用时间补齐，最多十个；没有选择也没有使用记录时不显示。常用应用在设置页的「App 栏」入口进入二级页面选择和拖动排序。系统分身身份继续保留。
- 格窗设置是一个单页，七组：常用应用（编辑入口、切换时收起上一个应用）、工作场景（把当前大窗和四个小窗存成一套，最多 8 套，恢复时按包名重新拉起；保存和恢复都要求工作台已打开；每套可添加桌面快捷方式，点击后快捷方式 Activity 把场景名交给模块的控制广播接收器就退出，由接收器打开工作台、等 1.5 s 再下发恢复命令并重试；ColorOS 首次需在应用权限页允许「创建桌面快捷方式」）、布局（跟随系统／浅色／深色、小窗靠左／靠右、控制区顶部／底部）、打开方式（控制中心开关、底角手势）、隐私（最近任务隐藏、本次允许截图／录屏）、遇到问题（导出诊断、退出工作台）、关于（版本、检查更新、署名）。布局、隐私和导出、退出这些偏好由 SystemUI 保存，设置页通过签名权限保护的控制广播读取和修改；截图许可只对当前会话有效，退出、锁屏、回桌面／最近任务或打开设置时复位。系统分享面板里有「发到格窗」：链接用默认浏览器、其他文字用默认搜索，在选定的大窗或某个小窗里打开；工作台没打开时提示并放弃。
- 控制区选择底部时，标题、常用栏和三个入口作为整体移到屏幕底部（横屏时移到手机物理底边），侧栏与主窗相应上移占满剩余区域（竖屏时侧栏从状态栏下方开始），窗口坐标、内容缩放和触摸区域一起调整，并为导航手势保留边缘余量。横屏全屏视频也收纳在所选位置。
- 模块弹窗使用 ROM 导出的 ColorOS 系统主题与原生控件；不覆盖系统弹窗背景或宽度。缺少 Oplus 主题时回退 Android DeviceDefault。
- 主窗任务请求横屏（例如视频点全屏）时收进宽窗，显示器保持竖屏不再整体旋转（清单里声明横屏的 Activity 不经过 setRequestedOrientation，system_server 在旋转策略处从方向来源补发场景并按住竖屏，否则 WindowManager 会先套固定旋转变换，面板被留在透明度 0、宽窗全黑），下方保留主窗和另外三个侧窗；竖屏全屏还需检测到媒体播放信号，避免游戏、阅读器等全屏应用被收纳。宽窗任务重新请求竖屏并显示状态栏后回到主窗。静音且没有媒体会话的竖屏播放器可能无法识别；识别依赖应用与 ROM。
- 顶部播放区直接接收触摸，可操作应用自身的返回、暂停或进度控件。退出横屏全屏后恢复该应用主窗及默认顶栏（以系统侧的竖屏请求事件为准；若宽窗里的任务换成了别的 Activity 而没有新的横屏请求，SystemUI 也会自行换回）；关闭任务则恢复四侧窗。系统不提供兼容的方向或全屏 Hook 时保留原生方向行为。
- 控制区无播放器控制。普通布局按一个主窗与四个原比例侧窗一起计算控制区和侧栏尺寸，侧栏约占短边五分之一；宽视频模式隐藏整个工具栏（图标、标题、日期、比价、支付、设置），视频使用完整控制区，退出后恢复。旧布局从已保存的屏幕和导航标定迁移。
- 主窗区域与原画面保持相同比例，竖屏上下贴合，横屏仅允许整数像素取整误差；不拉伸或裁掉内容。侧窗卡片匹配完整应用的比例；视频模式剩余空间放在卡片之间，不在卡片内部形成长条空白。
- 主窗与侧窗交换使用一个窗口事务同时设置父显示器和最终配置，异步观察画面就绪，不在交换路径阻塞 SystemUI 主线程。失败时回退原任务归属；退出或锁屏取消过期回调。
- 点击侧窗时，该窗的应用放大到主窗，原主窗应用缩小到该窗，侧栏和其余小窗位置不变。点击和拖拽交换都使用约220ms的同步位移、等比缩放，再等待任务交接就绪后淡出过渡层。过渡层按当前主题绘制面板、卡片和空窗加号，与淡出后的真实窗口一致；临时画面只存在于受保护的覆盖层内，结束或取消立即释放；无法取得内容时用卡片轮廓过渡，不关闭截图保护。移动中的画面同样不拉伸、不裁切。

## 付款与比价

支付图标弹出 ColorOS 系统弹窗，内容为四个原生行：微信扫一扫、微信收付款码、支付宝扫一扫和支付宝付款码，每项使用已安装应用图标与文字；未安装或无可用入口的项目变淡并提示，不会整个列表消失。优先查询目标应用公开的桌面快捷方式，再使用其已注册的启动入口；不读取账户、密码或付款码，也不自动确认支付。不随 APK 分发第三方品牌图片。

比价有两个分组：

| 分组 | 目标 |
| --- | --- |
| 外卖 | 京东秒送、淘宝闪购、美团外卖 |
| 购物 | 拼多多、抖音商城、京东、淘宝 |

输入一次商品词，在已安装并支持入口的应用中搜索同一内容。优先预留同一用户已打开的目标应用，然后使用空窗；窗口占满时，把需要替换的旧任务移到后台，不结束任务、不清除数据。第一个应用使用主窗，其余应用直接在预留侧窗启动。搜索路由创建新任务时，仅接管本次请求的新任务或已观察到的任务。跳转页不算完成：等待结果任务、目标显示器与画面稳定后再启动下一个应用。准备超时、启动或放置失败显示具体提示；取消停止后续启动。比价指并排查看应用搜索结果，不抓取价格、自动匹配同款、下单或付款。

这些应用内路由属于版本相关的兼容入口。京东商品搜索使用 `from=search` 并按客户端规则编码关键词；抖音使用 `search_style=commodity_center` 进入商城搜索；淘宝商品搜索等待 Browser 路由结束并进入结果页面。参数已通过用户复现日志和已安装 APK 的路由代码核对。本地回归覆盖布局、显隐恢复、搜索参数、预留替换、稳定结果观测与异步等待。未代替用户操作购物应用，也未宣称本版本已通过真机功能验收。

京东即时零售使用其公开前端的 `#/IndexSearch` 路由，淘宝闪购使用 `tb.ele.me/app/eleme/et-search/result` 和 `keyword` 参数；后者的搜索页脚本也用该路径进入结果页。美团使用公开客户端注册的 `/takeout/poi/search`，传入其搜索页读取的 `query` 参数。公开页面与路由的静态核对不代表当前安装版本的真机跳转已通过。

## 添加应用

主窗运行应用时点击空小窗的“＋”，先将原主窗应用保留在所点小窗，再显示桌面。下一次桌面或顶部应用点击在大窗打开新应用，原应用继续留在小窗，不结束任务或清除数据。若原主窗就是桌面、没有可保留应用，下一次选择仍加入指定空窗。再次点击同一个“＋”、退出或锁屏会取消选择；目标任务或显示已改变时拒绝使用旧选择。

桌面已显示时不再重复启动 HOME。工作台内的普通应用图标启动使用 ColorOS 原有的无源图标动画路径，保留原生启动检查、目标用户和后续启动流程；避免在侧窗接管前先准备一次整屏图标动画。外部链接和快捷方式继续使用原路径。

长按顶部应用图标拖入目标小窗，在该窗口打开应用。已有任务优先复用，工作资料或分身的目标用户信息保留。拖入已占用小窗会交换应用，原任务仍保留，原主窗会重新呈现；没有关闭或清除原应用数据。

启动请求被系统接受后，模块会等待实际任务出现，确认任务身份与目标显示后再移动；超时或系统拒绝会给出提示。应用入口和系统窗口能力仍需真机验证。

## 跨应用内容

在普通主窗＋四侧窗模式，从主窗应用长按照片或文件，发起 Android 全局拖动。拖入右侧已占用小窗时，目标从当前位置放大成为右侧主窗；原主窗及其他任务保持原顺序排入左侧侧栏。反向拖入左侧目标时对称处理。完整保留应用比例，以受保护的临时画面连接原生任务移动。

等待目标展开后，在目标应用支持接收的位置松手。扩窗沿用同一次原生拖拽，系统将数据直接交给目标当前页面；不再替换成 ACTION_SEND 分享界面。来源应用必须发起系统全局拖拽，目标应用必须支持原生拖放。URI 权限、跨用户限制和接收结果仍由系统处理，模块不代读文件、不提升内容访问权限、不自动发送消息。

未松手前可继续移动落点。取消、目标拒收或扩窗未完成就松手时恢复原布局；若应用已退出或更换了任务，保持任务身份校验并安全结束，不交换不相关应用。锁屏、关闭或方向重新配置会终止本次扩窗控制并释放预览。顶部固定视频模式本版不触发内容扩窗，需先返回普通四侧窗布局。

微信小程序沿用其真实任务：在系统最近任务中将已打开的小程序卡片置于中央，再点击空窗“＋”加入（沿用原有最近任务选择）。普通微信和独立小程序任务按任务 ID、根组件区分，普通应用入口不会仅按包名抢占小程序。

原主窗有应用时，目标小窗必须就绪并完成原任务迁移才进入桌面；准备失败保留原应用并提示，不隐藏它。没有原应用需要保留时，可先进入桌面，选择后再等待目标屏幕就绪。已绑定的屏幕被替换时取消旧选择，退出或锁屏会取消待处理启动。

## 显示和隐私

- 小窗使用普通 VirtualDisplay 与 SurfaceView，不要求宿主具备 `CAPTURE_SECURE_VIDEO_OUTPUT` 特权。工作台窗口的 `FLAG_SECURE` 和 SurfaceView 保护仍保留；不删除目标应用自身的安全标记，不保证 DRM 等受保护内容可显示。
- 默认保护工作台截图／录屏。“设置 → 一步工作台 → 本次允许截图／录屏”只对当前会话生效，退出、锁屏、回桌面／最近任务或再次打开模块设置时复位，不保存为永久开关。切换时四个小窗的输出表面会原地重建，因为 SurfaceView 的安全标记只对新建表面生效。
- 目标应用自身的系统保护、DRM、企业设备策略仍有效。允许截图不保证付款码、密码等内容可以被截取；显示兼容也需真机确认。
- 最近任务隐藏只过滤工作台当前拥有的任务，不删除任务或改写应用的永久最近任务标记；退出／暂停工作台即解除。
- 诊断导出只保存当前 SystemUI 进程内本模块最近128条事件元数据到下载目录，不抓取全量 logcat，不导出搜索词、拖动正文、URI、应用账户或画面。

## 安装和验证

这是预发布版。用户自行真机验证；构建、安装及加载核验不代表功能验收。没有操作付款账户或开展真实交易，也没有测量实际帧率、功耗或五应用长期并行稳定性。

可覆盖安装同一 Fork 签名的 corner／workbench 系列；本次升级后需重启手机，让 SystemUI、Launcher 和 system_server 同时加载新的运行协议。上游原版签名不同。内置更新仍指向上游，更新为上游包会替换本 Fork 功能。

本地回归包含旧配置迁移、四侧窗／宽窗在竖屏和两种横屏下的布局、控制区在顶部与底部的几何边界、几何快照跨进程编码、主窗与小程序任务区分、搜索词编码及窗口复用替换、内容授权边界、会话捕获权限复位，以及实际 Android View 的入口、日期、视频模式整个工具栏显隐恢复、浅深色实际像素着色、空窗加号尺寸、过渡层与真实卡片一致、常用栏只显示选择、付款四项渲染、拖动目标、搜索对话框回调、加号启动 HOME 与取消、异步交换等待和超时取消、路由临时页与结果任务区分。测试依赖只用于本地，不打包进 APK。

完整 Lint 仍有上游遗留的四项错误：`AppCompatCustomView`、两项 `SoonBlockedPrivateApi` 和 `WrongConstant`。构建与测试结果随 Release 的 `verification.json` 提供；不将 Lint 写成全绿。

## Shell 命令

注意：ColorOS 会冻结后台的格窗进程，经它中转的 `HOST_SET_REQUEST` 广播可能要等 60 s 才被处理；自动化脚本应直接向 SystemUI 发 `SET_WORKSPACE`，或先拉起格窗的任一界面。


原「高级」页的三条命令。以 Root 身份在手机解锁状态下执行，不加 `adb shell` 前缀；LSPosed 中需已启用本模块并重启。

- 进入：`am broadcast -n io.github.yishisanren.panes/io.github.lujinxin.nextep.trigger.WorkspaceControlBrokerReceiver -a io.github.yishisanren.panes.action.HOST_SET_REQUEST --ez io.github.yishisanren.panes.extra.REQUESTED_ACTIVE true`
- 退出：`am broadcast -n io.github.yishisanren.panes/io.github.lujinxin.nextep.trigger.WorkspaceControlBrokerReceiver -a io.github.yishisanren.panes.action.HOST_SET_REQUEST --ez io.github.yishisanren.panes.extra.REQUESTED_ACTIVE false`
- 查询：`settings get global nextep_workspace_active_v1`（1 小窗模式，0 普通模式，null 尚无记录）
